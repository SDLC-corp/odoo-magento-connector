Side by side

What you see in Magento, and where it lands in Odoo

Magento screens come from a Magento 2.4.9 store with Luma sample data. Odoo screens come from a connector demo database, so the two sides show different sample records.

Store overview → Magento Console

Magento's dashboard reports the store. The Odoo console adds the connector's view: orders, revenue and net profit per instance and period, plus unconfirmed orders, conflicts, open issues and the job queue.

Magento orders → Odoo sale orders

Each Magento order becomes an Odoo sale order with its customer, lines, taxes, shipping and payment mapped. The Magento increment ID, status, invoice and payment state stay visible on the Odoo order.

Websites and store views → Odoo instances

The connector imports websites, stores and store views, and each Odoo instance is scoped to a Magento website and store. Store views carry their language and currency, so localized product names and descriptions can be imported per view.

Sync failures → Error Center

A rejected attribute value, a timeout or a missing mapping does not stop the run. The record gets one Error Center row with the message, the payload and a link to the Odoo record, and it resolves itself on the next successful sync.

How recovery works

  • Transient errors, such as timeouts and rate limits, are retried by the job queue with bounded attempts.
  • Permanent errors, such as rejected data, are flagged for a fix, with optional alerts to chosen users.
  • Retry replays a failed push or stock job, and fetches a failed import again.
  • Resolve, ignore or retry issues in bulk, and filter them by entity, instance or error class.
  • Writes to Magento are idempotent, so a retried invoice, shipment or credit memo is never duplicated.

Catalog and configurable products

Products are imported page by page, picking up only records changed since the last run. Data ownership rules decide whether Magento or Odoo is the system of record for each area.

What synchronizes

  • Simple, virtual, downloadable, configurable, bundle and grouped products.
  • Configurable products become one Odoo template with a variant per child SKU.
  • Categories, attribute sets, attributes and product images.
  • Localized names and descriptions per store view.
  • Base, special and tier prices through price export rules.
  • Field mappings with transforms for product, customer and category fields.

What moves where

Each flow, and its direction

Magento → Odoo

Orders and customers

Orders with lines, taxes, shipping and payment mapping. Customers with their addresses become Odoo contacts.

Both directions

Products and categories

Import the catalog, or create products and categories in Magento from Odoo. Ownership rules prevent the two sides overwriting each other.

Odoo → Magento

Inventory and MSI

Map Odoo warehouses and locations to Magento Multi-Source Inventory sources. Stock changes are pushed as queued jobs.

Odoo → Magento

Invoices and shipments

Posted invoices and validated deliveries are sent to Magento, with carrier tracking numbers.

Both directions

Refunds and returns

Magento credit memos are imported as Odoo credit notes, and Odoo credit notes can create Magento credit memos. Returns can be routed back to stock.

Odoo → Magento

Prices

Price export rules publish base, special and tier prices per website and customer group.

Included capabilities

  • Manual and scheduled synchronization with incremental paging
  • Multi-company access rules and per-instance configuration
  • Dry-run preview and configurable system-of-record ownership
  • Order conflict tracking when items, prices, address, totals or status change after import
  • Bulk operations, reconciliation and order totals explanations
  • Daily operational digest and settings export/import
  • Adobe Commerce B2B entities where the matching Magento APIs are available

Security and reliability

  • Separate User and Administrator security groups
  • Credential fields restricted to connector administrators
  • OAuth 1.0a or bearer-token authentication, with SSL verification
  • Request timeouts, bounded retries and idempotent writes
  • Queued writes decouple Odoo transactions from Magento availability
  • Optional signed near-real-time notifications, with scheduled polling as the safety net

Requirements

Know what is needed before installation

Odoo

Odoo 20 Community or Enterprise with Sales, Inventory and Invoicing. This is a server module and does not run on Odoo Online.

Magento

Magento Open Source or Adobe Commerce 2.4.6–2.4.9 with HTTPS access to the REST API and an integration with permissions for the features you use.

Operations

Odoo cron must run for schedules and queues. Near-real-time push also needs the companion Magento extension, Magento cron and an HTTPS-reachable Odoo endpoint.
